# Протокол независимого контрольного набора

Версия: `independent-v1-2026-11-23`. Зафиксирован до первого прогона моделей.
SHA-256 канонического содержимого: `97d8404692fc8c8210ea86c8d2fbc7cb68cffbdec60c15e14a3cf070767eac9c`.

## Зачем он нужен

Аудит показал, что высокий macro-F1 на test Bitext не доказывает качество на
новых формулировках. Leave-One-Intent-Out (LOIO) использовался при выборе
архитектуры, поэтому его результат на тех же 25 интентах нельзя считать
независимой оценкой выбранной модели. Нужен отдельный набор, который не
участвовал ни в обучении, ни в калибровке, ни в подборе порогов, ни в выборе
признаков.

Набор создан после аудита. Это компромисс для учебного проекта: настоящих
обращений клиентов нет. Набор авторский, но порядок его создания и оценки
зафиксирован заранее, поэтому результат нельзя подгонять задним числом.

## Правила создания

1. Фразы написаны по публичным определениям 11 тем, а не по ошибкам модели.
2. Запрещено использовать train, calibration, val, test, `manual_cases`,
   `scenario_data`, `hard_test`, `ood_eval` и `risk_regression`.
3. Проверены точные совпадения и лексическое сходство с этими наборами и со
   всем CSV Bitext. Максимальное сходство с Bitext ниже 0.80, точных
   совпадений нет.
4. После первого прогона фразы не меняются. Если найдена ошибка разметки,
   выпускается новая версия набора, а старый результат сохраняется.
5. Набор не используется для настройки правил риска, порогов, каскада или
   промптов.

## Состав

| Часть | Объём | Что измеряет |
|---|---:|---|
| `independent_id`, режим `natural` | 55 (11 тем × 5) | обычные формулировки клиентов |
| `independent_id`, режим `no_keywords` | 55 (11 тем × 5) | те же темы без характерных слов |
| `independent_ood` | 20 | отказ от ответа вне области задачи |
| `independent_risk` | 16 | полнота и ложные срабатывания правил риска |
| `independent_multi` | 12 | выделение нескольких просьб |

`natural` и `no_keywords` оцениваются и публикуются раздельно. Их нельзя
усреднять в одну «красивую» цифру.

## Протокол оценки

1. Модель и политика фиксируются до прогона: `model_id`, версия политики,
   хеш артефакта, хеш набора.
2. Прогон выполняется один раз скриптом
   `python scripts/run_independent_benchmark.py`.
3. Для `natural` и `no_keywords` публикуются top-1, top-3, macro-F1, число
   ошибок и доверительный интервал Уилсона для доли верных ответов.
4. Для OOD публикуется доля обращений, которые теневая политика приняла бы
   сама, и верхняя граница Уилсона. Это частота ложных авторешений.
5. Для каскада публикуются: исправленные ошибки первой модели, внесённые
   новые ошибки, точность подсказок на принятых обращениях и число подсказок
   на OOD.
6. Для рисков и нескольких просьб публикуются precision, recall, нижняя
   граница Уилсона для recall и список промахов. Набор авторский, поэтому это
   регрессия правил, а не оценка реальной полноты.
7. Риск–покрытие строится на независимом наборе как справочная кривая. Она не
   является гарантией для рабочего потока.

## Заранее зафиксированные критерии провала

- `no_keywords` top-1 ниже 50% — модель не годится как основа подсказок без
  оператора.
- Доля ложных авторешений на OOD выше 5% — теневая политика слишком
  агрессивна.
- Каскад вносит больше ошибок, чем исправляет, — вторая ступень не даёт
  пользы.
- Recall правил риска ниже 80% — правила нельзя называть защитным контуром.

Провал любого критерия не переписывает набор. Он меняет выводы и приоритеты.

Прогон выполнен один раз на модели `router-c551bd5d209a4d1a`, политика

## Протокол few-shot сравнения с LLM

Если используется внешняя языковая модель, промпты фиксируются заранее:

- **Prompt A, описания классов.** Для каждой из 11 тем даётся название и одно
  предложение определения. Модель возвращает только название темы или
  `OTHER`.
- **Prompt B, два примера на класс.** Те же определения плюс по два примера
  из train на каждую тему. Модель возвращает только название темы или
  `OTHER`.

Температура 0, один запрос на обращение, модель и ревизия записываются в
отчёт. Примеры берутся только из train. Если внешняя модель недоступна,
отчёт фиксирует `NOT_RUN` и не подставляет выдуманные числа.

## Ограничения

- Набор авторский и синтетический, а не выборка клиентов.
- Разметка сделана автором проекта, без независимого эксперта.
- Фразы писались после аудита, поэтому полной неосведомлённости нет.
- Результат описывает устойчивость к данным формулировкам, а не качество в
  продакшене.
